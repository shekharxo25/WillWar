# PWA and native feel (Part 6.3)

## Manifest (`src/app/manifest.ts`)

`id` "/app/", `scope` "/app/", `start_url` "/app/today?source=pwa", `display` "standalone", name and short_name "WillWar" (discreet), theme and background `#0E0E0E`, icons 192, 512, maskable and monochrome, shortcut "Go a round" → `/app/round`.

## iOS head tags

`apple-touch-icon` 180 (opaque), `apple-mobile-web-app-capable`, status bar `black-translucent`, launch images (`src/components/shell/launch-images.ts`, generated by `npm run icons`), `viewport-fit=cover`.

## Service worker (`public/sw.js`)

- Scope `/app/`, registered by `src/components/shell/RegisterSW.tsx` in production only.
- Precache the shell and `/app/offline`. NetworkFirst for app pages (fallback to cache, then `/app/offline`). StaleWhileRevalidate for Learn and static assets. **Never cache `/api/*`.**
- Bump the cache version on release: `node scripts/stamp-sw.mjs` (defaults to the git short SHA).

## iOS realities

- No install prompt: Share → Add to Home Screen (since iOS 26 sites open as web apps by default).
- Web Push only for installed apps and only from a tap.
- No Background Sync: the IndexedDB queue drains on load, focus, online and visibilitychange.
- Sign-in uses 6-digit email codes, because magic links open in Safari instead of the installed app. Test Google OAuth inside the installed app.

## Layout and touch

Safe-area insets everywhere, `100dvh`, `overscroll-behavior: none`, no tap highlight, inputs ≥16px, `touch-action: manipulation`, `user-select: none` only on chrome and game canvases. 44pt minimum targets.

## Native touches

App badge when today's check-in is pending; Screen Wake Lock during rounds; Web Share for invites; `navigator.storage.persist()` after install.

## Discretion

Notifications default to "WillWar: Day 12. Tap to check in." Email subjects are plain. The manifest name and in-app titles never mention the challenge's subject unless the user turns discretion off.
